# Labels

Each open issue gets one type label and one priority label.

## Type

| Label | Use it for |
| --- | --- |
| `bug` | The tool does something wrong, crashes, or gives a wrong diagnostic. |
| `enhancement` | A new rule, flag or output format, or a change to how one works. |
| `documentation` | The README, a guide or a doc comment is wrong or missing. |
| `question` | The reporter wants to know how to do something. |

## Priority

| Label | Meaning |
| --- | --- |
| `P1` | Crash, data loss or a broken release. Fix before the next release. |
| `P2` | A real problem with a workaround. Plan it for the next few releases. |
| `P3` | Nice to have. Pick it up when there is time. |

## Status

| Label | Meaning |
| --- | --- |
| `needs-info` | Waiting on the reporter. Close after 30 days with no reply. |
| `duplicate` | Another issue covers it. Link to that issue before closing. |
| `good first issue` | Small, well described, and needs no deep knowledge of the code. |
